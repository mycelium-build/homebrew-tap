# Mycelium Build Homebrew tap

Install Datalith on macOS with Homebrew. The casks use the signed and notarized
DMGs published in [Datalith releases](https://github.com/mycelium-build/datalith-app/releases),
with automatic selection of the Apple Silicon or Intel build.

## Install

Stable:

```sh
brew install --cask mycelium-build/tap/datalith
```

Preview:

```sh
brew install --cask mycelium-build/tap/datalith@preview
```

Both applications can be installed together. Each keeps its integrated updater
and receives updates from its own channel.

## Automation

After a Datalith release, the application repository triggers
[update.yml](.github/workflows/update.yml) with the release tag.
[scripts/update.py](scripts/update.py) selects the latest published version in
that channel, verifies both DMGs' checksums, signatures, notarization and app
identity, then generates the cask. Homebrew checks run before the workflow commits
the update automatically.

The notification uses the existing automation GitHub App with **Actions: write**
access to this repository. The tap workflow uses its own `GITHUB_TOKEN` to commit
to `main`.

To rerun an update, launch **Update Datalith casks** in GitHub Actions. Supply a
release tag for one channel, or leave it empty for both. Set `publish: false` to
review the generated diff without committing it.

## Contributing

Open a pull request for changes to the casks or automation. Cask definitions are
generated by `scripts/update.py`; update its template when changing their structure.

On macOS, with Python 3, an authenticated GitHub CLI (`gh`) and Xcode command-line
tools installed:

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/update.py
brew style Casks/*.rb
```

[Check tap](.github/workflows/check.yml) runs the tests and Homebrew style/audit
checks on pull requests.
